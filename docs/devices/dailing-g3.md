# DaiLing G3 无线耳机 — 协议分析记录（未完成）

状态：**暂不支持**。普通版 G3（`3654:4255`）在电脑上**连官方软件都不显示电量**。

## 硬件

| 项目 | 值 |
|---|---|
| USB ID | `3654:4255`（普通版）/ `3654:5055`（S-drive 版） |
| HID 厂商字符串 | `Jieli Technology`（杰理方案） |
| HID 接口 | MI_03：COL01 Consumer（3 字节）、COL02 `FF02/0002`（报告 `02`，64 字节）、COL03 Consumer（报告 `ED`/`FD`，32 字节，Feature `ED` 16 字节） |

## 官方软件

| 软件 | 支持的 PID | 说明 |
|---|---|---|
| DAILING Audio Center 1.0.0.5 | 4255 | C-Media XearONE（.NET），只负责 7.1 音效。电量协议：写 `55 65 01`，设备推送 `55 65 <电量%> <充电>`。**本设备没有报告 ID `0x55`，写入返回错误 87，所以不适用。** |
| DaiLing HUB 1.0.20.1 | 5055 | Flutter + hidapi，协议层 `cs_protocol`。开机后向所有接口发送探测帧 `<CD/CE> 07 AA 5A CC 80 51 01 02`。 |

## 已经尝试过的

- 被动监听所有接口 5 秒：没有收到任何主动推送
- 用 GetFeature / GetInputReport 读取所有报告 ID（只读）：只有 `ED` 返回 `ED 07 00 05 00 01 02 0A 0D`，看起来是功能列表，不是电量
- 用 hidapi 代理把 HUB 的 PID 5055 替换成 4255：HUB 能打开设备，但它用的报告 ID `CD`/`CE` 本设备不支持，写入失败
- 把同样的探测帧换成报告 ID `02`（COL02）或 `FD`（COL03）发送：没有回应

## 后续可以试的方向

- 在 Windows 上抓包（USBPcap），对象是**普通版 + 官方 App 或手机 App**（如果手机 App 能显示电量，说明耳机本身会上报电量）
- 改用蓝牙连接：Windows 的蓝牙电量属性可能可以读到
